# DichromaticMap 全仓库审阅报告（2026-10-14）

## 审阅基线与结论

已获取并同步远端 `main`；审阅时的最新代码为 `f093e9eff66601dcdde14cc95d79e236b836ee1e`，版本号为 `0.2.2`。覆盖共享数值模块、Qt 桌面交互、网页及 Worker、GPU、移动交互、教程、会话与 CSV/PNG 导出、文档构建、CI 和原生发行脚本。本次产出审阅报告，尚未实施下面的功能修复。

本轮确认的问题按影响排序：首先修复物理角度与异步结果不一致、应变状态被快捷键破坏、PNG 使用旧测量读数；随后修复跨端恢复、交互与数值 API 边界。性能改进应优先减少无效工作和主线程阻塞，保持原子身份、计数、应变条件及 Float64 科学计算不变。

优先级：**P1** 为会话不可再保存/恢复或科学输出快照不一致；**P2** 为功能错误、交互失真或公开数值 API 的正确性问题；**P3** 为低影响、特殊输入或较少见的边界。发行覆盖不足另列，不能当成已证实的安装包故障。

位置均对应上述基线，采用代码路径与行号，避免文档源码包因缺少 `.github` 文件而构建失败。

## 一、已复现的主要问题

### B01 / P1：网页在计算结束后吸附角度，破坏会话及搜索的物理一致性

- **位置**：`site/web_bridge.py:90–92`；`site/use.js:474`、`1068–1070`；桌面会话精度契约见 `src/dichromatic_map/session.py:267`。
- **复现一**：合法桌面会话保存 `38.94344126898139°`（Σ9 + 0.001°）和两个实际选点。网页导入后，render 把角度吸附到 `38.94244126898139°`，却保留原选点；坐标漂移约 `4.4e-5 a₀`，再次保存报 `Inconsistent atom position`。
- **复现二**：网页启用应变搜索、输入 `38.94°`，render 响应晚于 150 ms 的搜索防抖。搜索按 `38.94°` 计算，render 随后改变角度；搜索签名删除了 angle，旧角度的三个真实候选仍被接受，保存报 `Inconsistent common-cell translations`。
- **修法**：普通交互需要吸附时，在所有物理任务发出前统一规范化；导入明确保留存档精确角度。结果必须核对实际计算的角度和完整物理输入，不能通过忽略 angle 接受不相容结果。
- **两端验收**：同一 `.dmap` 在桌面→网页→桌面往返后，角度、选点、F、平移、共同胞及 CSV 保持一致；覆盖慢 render、近预设角度与先后不同的返回顺序。桌面已有保存角度精度的行为，应作为共同契约。

### B02 / P1：网页快捷键 M 绕过已施加应变的编辑限制

- **位置**：`site/use.js:1702`、`984`、`845`；桌面保护在 `src/dichromatic_map/ui/window.py:454–458`。
- **复现**：导入一个合法、已有四顶点手动应变的会话，按 M。顶点变成零个，fit、original 和 F 仍保留；Restore 被禁用，保存报 `Manual strain fit requires four paired vertices`。
- **修法**：在模式转换函数内部统一检查编辑权限；按钮、快捷键和导入后的操作共用保护，不能只禁用按钮。恢复原始结构的入口必须保持可达。
- **两端验收**：已拟合状态下，按钮和键盘不能破坏四顶点；恢复后可重新选点、保存和导入。网页向桌面的现有保护对齐。

### B03 / P2：修改颜色等显示设置，会静默丢弃有效分析

- **位置**：`site/use.js:1066–1080`、`1278`、`1284`。
- **复现**：应变搜索中改 G1 颜色，结果返回后列表仍为空，状态停在 Searching；在防抖期间改颜色，则任务根本不发送，停在 Waiting。签名包含完整会话及设置，却没有相应重启。
- **修法**：按动作签名真实输入，区分物理版本与显示版本；真正失效时明确取消或重启。颜色、参考轴等不应让物理搜索失效。计数的区域过滤等确实影响结果的设置仍须纳入签名。
- **两端验收**：外观调整不丢物理结果，改变角度/应变/计数边界仍拒绝旧结果；两端采用同样的输入依赖规则。

### B04 / P1：PNG 等待几何计算，却没有等待当前向量读数

- **位置**：`site/use.js:1132–1156`、`1497`、`1302`、`1328–1335`。
- **复现**：已有 axial repeat 0 的向量读数，改为 1，延迟 vector 响应并立即导出。PNG 已下载，仍画入 `axial +0` 的旧方向与长度，当前设置却是 1。
- **修法**：读数绑定输入签名，输入变化后隐藏旧值或标为更新中；导出等待相应读数，或只绘制与导出快照相符的读数。几何、标题、注释和测量表应来自同一个快照。
- **两端验收**：在延迟响应条件下检查实际 PNG 文字、方向和长度，并与桌面 PNG 及 `.dmap` 的 `vectors.csv` 对照。桌面的同步读数路径也加入同类回归。

### B05 / P2：网页导入视野只考虑 X 跨度，裁掉存档中的 Y 范围

- **位置**：`site/use.js:1413–1415`、`156–160`；桌面恢复见 `src/dichromatic_map/ui/session.py:249–250`。
- **复现**：在受控 UI harness 中，合法视区 `[-2,2,-20,20]` 导入 1024×852 页面后，变为约 `[-2,2,-1.635796,1.635796]`，Y 跨度从 40 缩至 3.27。
- **修法**：结合容器比例，用 `max(X跨度, Y跨度×绘图区宽高比)` 适配；可以扩展较短方向，但不能裁掉原范围。超出网页视野能力时明确说明，避免静默截断。
- **两端验收**：窄高、宽矮、平移和旋转的存档，在不同窗口尺寸下均包含原视区；重新保存后仍满足包含关系，并保持中心和物理选点。

### B06 / P2：轴向重复的小数输入被 Python 截断，显示和计算不同

- **位置**：`site/use.js:1497`、`1141`；`site/web_bridge.py:265`。
- **复现**：输入 `1.5` 可进入 change handler，标签显示 `+1.5`；bridge 用 `int()` 按 1 计算。真实输入的 repeat 1 和 1.5 得到同一位移 `[1,0,1.41421356]`、长度 `1.73205081`。
- **修法**：UI 和 bridge 都严格校验整数及 `[-4,4]` 范围，拒绝小数、空值及非有限值，不能截断后继续。
- **两端验收**：桌面整数 SpinBox、网页和数值入口采用相同范围；标签、向量和 CSV 对应同一个整数。

### B07 / P2：组合快捷键意外执行应用单键操作

- **位置**：`site/use.js:1697–1706`。
- **真实浏览器复现**：Ctrl+C 把中心 `[4,-3]` 改为 `[0,0]`；Ctrl+F 把区域过滤 `[true,false,false,true]` 改为全部 true。代码只看字符，没有排除 Ctrl/Meta/Alt。
- **修法**：排除组合修饰键、IME composing、已处理事件及可编辑节点，保留普通 C/F 的功能。
- **两端验收**：复制、浏览器查找不改变视野和 GB 过滤；普通单键仍正常。桌面的 `QShortcut` 使用完整键序列，应保留该行为并加入对照测试。

### B08 / P2：拖动角度时窗口变尺寸，显示比例失真

- **位置**：`site/use.js:441`、`458`、`702–704`、`1709`。
- **真实 resize 复现**：从 1440×900 改为 900×650，held 模式只更新 canvas metrics，模型高度仍是旧值。X 为 `35.0833 px/a₀`，Y 为 `54.6115 px/a₀`，纵向多拉伸约 55.7%；释放后才恢复相同比例。
- **修法**：视口尺寸变化时先同步模型宽高，再安排绘图；保持拖动中的 Worker 隔离，不必解除 hold。
- **两端验收**：拖动并 resize 时始终满足 X/Y 相同单位缩放；Qt 的锁定纵横比也验证。底层角度没变，但该失真会误导对夹角的观察。

### B09 / P2：另一触点的释放会提前结束角度拖动

- **位置**：`site/use.js:957–975`、`1464–1465`。
- **原生 mouse+touch 复现**：鼠标 pointerId 1 按住角度滑条，另一手指 pointerId 2 点击后释放，hold 已变 false，鼠标却仍按着。
- **修法**：记录拖动拥有者 pointerId，只有其 up/cancel 才结束；change、blur、引擎失败等保持显式结束语义，并正确处理 lostpointercapture。
- **两端验收**：多指、鼠标加触摸、无关 cancel、真正释放、失焦及等待导出；Qt 原生滑条验证相同释放契约，无须复制浏览器指针代码。未确认此问题损坏最终科学数据，主要影响交互和计算频率。

### B10 / P2：高层及数字符号的网页图例错误，PNG 同样受影响

- **位置**：`site/use.js:796`、`802`、`1317`。
- **复现**：FCC ⟨1 1 3⟩共 11 层，只显示 G 层，两晶粒各有 138 个点，但图例没有 G1/G2 · G；`number:7` 在图中含 7，图例却显示普通圆。
- **修法**：从可见层并集取有限项，数字标记保留编号；屏幕和 PNG 共用图例模型。省略其他可见层时给出简短提示。
- **两端验收**：桌面已按可见层取图例并使用真实数字 marker；网页对齐。测试第七层、非连续层、数字标记和普通/clean PNG。

### B11 / P2：移动页面放大后，教程导航可能完全出屏

- **位置**：`site/tutorial.js:87–100`、`179`；`site/use.css:219–220`。
- **复现**：390×844 页面放大 2×，visualViewport 为 195×422，气泡仍宽 340；Next 在 x=293–348、y=714–750，不在可见区。
- **修法**：以 visualViewport 的尺寸与偏移限制气泡和定位，监听其 resize/scroll；保证内容可滚动，关闭与下一步可达。
- **两端验收**：移动页面放大、平移、软键盘及地址栏变动。该问题仅属于浏览器 UI，不需要修改 Qt 数值计算。

### B12 / P2：桌面搜索的空消息异常被当成成功，并缓存空结果

- **位置**：`src/dichromatic_map/compute.py:290`、`304`、`332`、`337`；`src/dichromatic_map/ui/window.py:1406`。
- **复现**：活跃任务抛 `ValueError()`，或调用方 executor 取消仍被轮询的 future。`str(error)` 是空串，真假判断不认为失败，`poll()` 返回并缓存 `[]`；同参数重试继续命中空结果。
- **修法**：保存异常/显式状态，以 `is None` 判断，显示消息补异常类型兜底；仅成功结果可缓存，包括合法的成功空结果。
- **两端验收**：异常、取消、同参数失败后成功重算；Web Worker 已用显式 error 类型，补对应回归，避免两端把“失败”和“没有解”混淆。

### B13 / P2：大整数胞的原子数发生 int64 溢出

- **位置**：`src/dichromatic_map/cells.py:242`、`260–262`；`src/dichromatic_map/strain.py:253`；`src/dichromatic_map/completion.py:41`。
- **复现**：SC [100]、边长 `3,100,000,000` 的相同整数胞，拟合和三点补全成功，但 atoms 为 `8,836,744,073,709,551,616`，正确值是 `9,610,000,000,000,000,000`，并出现乘法溢出警告。
- **修法**：2×2 determinant 在乘法前转换为 Python 整数；其他矩阵转换/列操作同步检查范围，明确拒绝不支持范围或采用精确整数路径，不能在溢出后才 `int()`。
- **两端验收**：共享核心、标签和 CSV 的整数一致；普通 index≤40 的搜索不触发此大小，大数问题属于公共 API。更大的值还须核对 JS 安全整数和会话既有范围，不能只修 Python 标签而丢失跨端精度。

### B14 / P2：可行拟合在大坐标平移后被误拒绝

- **位置**：`src/dichromatic_map/strain.py:329–334`，两端及补全均调用此入口。
- **复现**：SC [100]、0°、49/51 两正方胞、2% 应变、0°附加旋转，原点处成功；同时平移到 `[60,000,000,60,000,000]` 后失败。最大顶点为 `60,000,051`，仍在会话坐标上限内。
- **证据**：中心化残差为零；`F*x+t` 的抵消产生 `1.0536712e-8` 残差，略超过 `1e-8`，该坐标 ULP 为 `7.4505806e-9`。
- **修法**：局部原点验证与稳定仿射求值，连同实际晶粒重生成及导出一起检查；不能只放宽科学阈值或强制平均两侧原子。
- **两端验收**：平移前后 F、周期、应变限制一致；实际重生成端点也相容，并保留真正不可行四点的拒绝。在 Native/Pyodide 分别验证。

### B15 / P2：匹配 bin 的浮点精度不足，漏掉容差内的原子

- **位置**：`src/dichromatic_map/matching.py:54–62`。
- **普通跨度的 API 复现**：float32 的 first=`[[-32,0],[1.8e-6,0]]`、second=`[[2.7e-6,0]]`、tol=`1e-6`，实际距离约 `9.0000015e-7`，却返回零匹配。减去共同原点后仍用 float32，bin 相差四格。
- **补充**：float64 极大跨度也会丢 bin 分辨率。例如 first=`[[-2**33,0],[.49*2**-20,0]]`，second 近点再加 `9e-7`，tol=`1e-6`，同样漏匹配。
- **修法**：bin 运算明确升到 Float64；再检查浮点分辨率，极端跨度局部锚定分区或明确报精度范围错误。不能靠增大物理容差掩盖遗漏。
- **两端验收**：共享匹配与直接距离 oracle 对照，覆盖 dtype、平移、bin 边界、顺序、互为最近邻及 tie。现有两端生成器输出 Float64，普通 UI 没有复现上述 float32 输入分支。

### B16 / P2：大平移让生成器的裁剪容差膨胀

- **位置**：`src/dichromatic_map/crystal.py:569`、`579–582`。
- **复现**：`projected_columns(2,2,0,center=(1e12+.2,0),lattice='SC',axis='100')` 返回 30 个点，要求的矩形内只有 6 个；还包含 y=±2，要求是 y∈[-1,1]。全局坐标乘 `1e-10` 使 epsilon 约为 100。
- **修法**：使用局部视野尺度和合理的逐坐标 ULP/运算误差界，必要时采用局部锚点；精度无法满足时明确拒绝。
- **两端验收**：独立晶格枚举对照大平移、旋转、F、层和 halo，保留边界及 half-indices。属于公开生成 API 的大坐标问题；两端还会再次裁剪显示，此证据不等于普通视野的可见原子计数错误。

## 四、安装包与网页的同步、发行覆盖

### R01：两个分发渠道并非自动同步

Pages 在 main 更新后自动构建；原生包只在 tag 或手动 Release workflow 构建。远端 `v0.2.2` 指向 `6723f978137e15e5eee8935b84e1c5643e9172bf`（2026-09-29），审阅 main 比它多31个提交，11个共享/桌面 Python 文件有差异；网页与包仍能同时显示版本 `0.2.2`。这证明版本号不足以识别相同源码，不据此推断用户实际安装了哪一次构建。

共享 Python 改动会进入新网页 vendor zip 和新原生构建，**不会自动升级已经发布或安装的旧二进制**。建议记录源 commit、核心源码摘要、版本和依赖版本，在两端显示构建身份；从一个审定提交生成网页与四平台原生候选，统一通过验收后发布新的版本。保持网页渠道可快速更新，但明确该改进已进入哪些安装包版本。

位置：`.github/workflows/pages.yml:4–5`、`.github/workflows/release.yml:4–6`；`scripts/build_site.py:28–32,46–48`；`scripts/build_executable.py:29–33`；`packaging/DichromaticMap.spec:15–21`。这是同步及可追踪性改进，不是已证实的构建故障。

### R02：源代码 GUI 通过不等于所有冻结调度路径通过

原生冻结烟测已有小视野、真实进程提交、保存/导入往返及 PNG，不应说成未测安装包。但 `scripts/frozen_smoke.py:75–95` 主要使用 axis100、6×4；直接提交 Worker 没有覆盖 `compute.py:404–443` 在 `point_count≥100,000` 且 `layer_count≥4` 时的预热/进程切换，以及任务进行中的取消、关闭、重入和错误恢复。

建议在预发行提交测试这些真实冻结场景；普通 PR 至少覆盖一个原生构建，完整发行覆盖 Linux、Windows、macOS arm64/x86_64。当前仅是验证缺口，没有据此确认安装包必然失败。本次也没有制作四平台安装包。

### R03：正常显示后端及真实设备覆盖有限

`scripts/smoke_executable.py:30–36` 强制 offscreen，需补 XCB/Wayland/Cocoa 的正常首次启动和基本操作。浏览器 CI 当前使用 Chromium、SwiftShader、固定桌面视口；本轮追加移动模拟/页面缩放等受控复现，但 Safari/Firefox、真实手机和硬件 GPU 仍需回归。不把未测试平台直接写成故障。
